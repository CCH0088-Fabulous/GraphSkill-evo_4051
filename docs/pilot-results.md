# 双数据集 pilot 记录

2026-10-30 的第二批 pilot 已完成两个数据集的无技能、初始技能、原始 GraphSkillEvo 一轮进化，以及最终选定技能的独立验证。
每个数据集使用固定的 10 条训练、5 条验证、0 条测试样本。进化过程只读取训练与验证；基线和独立验证在各自数据集使用相同的五条验证 ID。
这批结果用于验收流程，不能视作正式测试结果；五条验证样本也不足以证明效果提升。

模型为本地 Qwen3.5-9B，BF16 / SDPA，thinking 关闭，随机种子 42。本批次临时覆盖温度 0.6、总上下文 16384 token、请求超时 360 秒；
普通问答上限 2048，技能算子上限 4096。两数据集和全部条件使用相同设置，模型文件指纹一致。
该次运行时，根 `config.yaml` 仍是温度 0.0、上下文 8192、超时 180 秒；当时的 pilot 覆盖值没有写入根配置。
后续已完成两轮资格验收并冻结 v1，当前规则见 `docs/frozen-settings-v1.md`；本文件保留早期 pilot 的历史记录。

## 需要在正式实验前处理的问题

1. 两个数据集的训练过程中各有一条回答达到 2048 token 上限后被截断，这两条均被作为训练失败反馈给优化器。
   一条为 SearchQA `a4375645235745baac2b0253713ff424`，另一条为 HotpotQA `5a8749a35542996432c57250`。
   这说明部分失败反映了输出超限；后续应核查回答长度、提示词和输出上限，并与 B、C 确定统一处理方案。
2. 两个数据集的 `mutation_graph` 各有 10 次无效生成重试，重采样另一父代后才成功。每次 HTTP 调用和消耗都保留在账本中。
   同一提示和固定种子会反复得到相同输出，应在正式预算估算中考虑这一现象，不应把 HTTP 成功等同于图结构生成成功。
3. 第一批温度 0.0、8K 上下文的 SearchQA 进化未完成：图结构多次无效，随后请求所需 5211 输入 + 4096 输出 token 超过 8192 的窗口。
   该失败批次保留在 `outputs/pilot-check/20261030T014736845332Z-a402ff/`；其一次失败调用没有返回 usage，记录为未知。
   之后用相同原始提示做了一次 16K、温度 0.6 的图格式探针，再运行本批完整 pilot。
4. 一轮只覆盖 `mutation_other` 和 `mutation_graph`；交叉算子需要至少两轮的进一步验收。
   课程规模的 30 条验证、更多轮和更长反馈也需要重新测量，不能根据本次结果保证正式运行一定不会超时或超限。
5. HotpotQA 当前使用自行固定的公开数据子集，未核验为课程专用划分；模型文件上游 revision 也未独立核验，正式报告需如实说明。
