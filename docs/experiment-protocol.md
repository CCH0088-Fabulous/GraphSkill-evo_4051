# 实验运行约定

本文件约束共同运行方式；B 的研究改进仍只改变训练失败案例选择，C 维护评分与分析。

## 固定条件

原方法、改进和消融共享模型及权重版本、precision、thinking、解码、输入处理、上下文、每次生成上限、超时、重试、调用和生成 token 预算。
GPU 小时是实测资源记录与规划参考，不作为决定候选排名的指标。相同进化轮数不能代替预算匹配。

`course` profile 检查每数据集最多 100/30/50，最多三轮、每轮最多两个新候选。
`custom` profile 可用于其他明确披露的规模；它不允许进化过程访问测试集。
`synthetic` profile 只能搭配明确标记的合成数据，其运行不计为真实独立模型实验。

初始种群与每轮新候选数是不同概念。课程适配默认保留种群为二，每轮两个新候选，
按 mutation_other、mutation_graph、crossover_other、crossover_graph 跨轮轮转。
一轮 pilot 仅验证完整接线；两轮及以上才能覆盖默认的四种算子。
最多六次算子逻辑尝试/阶段单位，初始化与每轮有独立上限；HTTP 重试由 client 负责，每次请求单独记账。

## 划分和反馈

先冻结 ID 和原始/标准化数据校验值，再查看实验结果。
SearchQA 使用论文代码发布的划分清单。公开 HotpotQA 子集的来源和自定义划分必须披露，后续拿到课程清单可另建数据目录替换。
本项目当前关注答案 EM/F1，不将 HotpotQA 支持事实指标伪称为答案指标；支持事实仅保留在源数据中，不能给模型答案提示。

训练执行结果和训练参考答案可形成优化反馈。开发成绩用于父代、幸存者、最终技能选择，开发失败供方法诊断。
进化 dataloader 只持有训练和开发数据；正式留出测试须在方法/配置冻结后独立评估。
重复使用小开发集可能过拟合，应在报告中披露。

## 可追溯计量

模型请求统一经过 `inference/client.py`；后台自动重试不可绕过账本。
未知 usage 保留生成额度预留并标记缺失，不能自动填成零。模型输出缓存不算作新独立运行。
验证技能内容的缓存只在单次独立运行内使用，上游记录明确标记复用。
单题 latency 包含失败重试等待；`last_request_latency_s` 单列最后一个请求。
GPU 监控记录显存、利用率、功率和监控墙钟时间，它不是 CUDA 内核运行时间，也不证明 GPU 独占。

结果表必须来自独立加载的最终技能评测。进化过程重复采样的训练预测可用于诊断，不能混入最终测试平均分。

## 基本验收与当前进度

先用 `repro smoke` 检查合成数据的完整接线，再用 `scripts/run_example.py` 检查本地真实模型。
双数据集 pilot 使用 `scripts/run_pilots.py`，检查初始化、训练反馈、候选生成、开发评分和最终技能保存，以及失败重试、输出截断和未知 usage。
默认一轮；需要覆盖四种算子时使用 `--set evolution.generations=2`。pilot 数据不含测试样例。

课程规模的单种子开发集实验已完成，两个数据集各三轮，并包含无技能、初始技能及选定技能对照，详见 [正式开发集结果](formal-results.md)。测试集仍未评估。
早期 pilot 和 v1 资格验收记录位于 [历史归档](archive/README.md)，旧参数及命令仅用于解释当时结果。
