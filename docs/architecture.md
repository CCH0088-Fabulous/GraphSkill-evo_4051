# 职责与依赖边界

每个模块按一种主要变化原因组织。优先适配固定版本的官方实现；课程缩减、数据适配和日志扩展放在项目层，
保持原方法与后续改进共享运行、评分和预算规则。

| 位置 | 单一职责 | 主要负责人 |
|---|---|---|
| `cli.py` | 解析命令、装配组件、选择用例 | A |
| `config.py` | 读取配置、解析路径、验证约束 | A |
| `contracts.py` | 公共记录和接口定义，无副作用 | A / B / C |
| `datasets/` | 原始数据适配、ID 清单、划分校验 | A / C |
| `inference/client.py` | 模型协议请求与响应适配 | A |
| `inference/accounting.py` | 调用、token、失败重试预算计量 | A |
| `serving/model.py` | 加载并执行本地模型，校验上下文 | A |
| `serving/app.py` | 本地模型的 HTTP 协议边界 | A |

| `selectors/` | 每轮训练失败案例的选择 | B |

| `diagnostics.py` | 只读检查环境和所需文件 | A |

## 公共契约

`QAExample` 统一 `id / dataset / split / question / context / answers / metadata`。
`split` 只使用 `train / val / test`；在官方适配层映射为其内部名字。
原始结构应保留在 metadata 或原始文件中，格式统一不能抹掉课程数据来源和划分边界。

`Generation` 是一次模型响应及其 usage；`Prediction` 是一条样本的输出、答案、成绩、延迟和失败状态。
结果应关联运行 ID、条件、技能版本及固定数据清单，C 可以据此独立重算和检查。

## 选择器与评分边界

B 的失败案例选择器只选择训练失败池中的样例，不改写优化提示词，不承担父代、幸存者或最终技能选择。
父代与幸存者的验证选择使用共同逻辑。尚未实现的 improved / ablation 应明确拒绝运行，不能偷偷回退到原选择器。
C 拥有评分及分析代码，A 的编排层调用统一接口，避免每个实验重新实现 EM/F1。

## 数据和运行隔离

训练材料可形成技能更新反馈，验证材料用于技能选择及方法诊断。方法冻结后才运行正式留出测试。
不同实验使用独立产物目录，配置中保存随机种子、模型设置、数据 ID、源码 commit、调用与 token 上限。
资源小时数只用于估算，实际用量应包含初始化、执行、修改、失败与重试。
缓存模型输出必须标明复用，不能算作新的独立模型实验。

## 图的两个层次

技能内部流程图展示任务路由、节点、执行顺序、显式条件和分支；候选谱系图展示初始化、父子关系、验证成绩和保留决定。
两者分别保存，前者满足技能结构解释，后者帮助追溯进化过程。
